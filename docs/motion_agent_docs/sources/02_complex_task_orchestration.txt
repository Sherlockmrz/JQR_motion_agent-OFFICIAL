基于现有运动agent进行新增对复杂任务的任务编排和执行计划，初始版
目标是：
复杂自然语言
→ LLM一次生成完整步骤和depends_on
→ compile_plan()检查工具、参数、依赖、循环、结果条件
→ run_plan()判断ready步骤
→ 物理任务最多一个，只读任务最多四个（并行）
→ 调用现有agent.execute_task()
→ 根据真实结果继续、失败或停止

所以这些任务目前存在两个问题：
1. 使用ROS/MCU共享通信链路。
2. 可能阻塞整个 asyncio 事件循环。
在逐项验证和改造成非阻塞调用前，保守放进物理锁。

class SimpleOrchestrator:
    def 
__init__
(self, agent, logger):
        self.agent = agent
        self.logger = logger

from typing import Any
@dataclass(frozen=True)
class ParamRule:

      "id": "open_box",

      "id": "check_box",
      "title": "确认药箱状态",
      "type": "get_medicine_box_status",
      "params": {},
      "depends_on": ["open_box"],
      "expect": {
        "path": "/state_name",
        "op": "eq",
        "value": "open"
      }
    },
    {
      "id": "find_zhang",
      "title": "寻找张三",
      "type": "go_find_person",

      "depends_on": ["find_zhang"]

  "reason": ""

这里：
- id：本次计划内部的步骤名。
- title：中文AgentLog使用。
- type/params：直接对应当前代码。
- depends_on：业务依赖，不是硬件资源冲突。
- expect：规定工具返回什么结果才算真正成功。

九、一次性生成全部步骤和depends_on的Prompt
核心是：
1. 把可用工具和参数全部给模型。
2. 明确要求一次返回完整JSON。
3. 禁止边生成边执行。
4. 要求模型区分业务依赖和资源冲突。
5. 编译通过前机器人不执行任何动作。
建议Prompt如下。

十、compile_plan()
输入是LLM生成的计划草稿，输出是程序确认可以运行的计划。
它主要检查：
1. 计划是不是合法JSON结构。
2. 每个步骤是否有唯一名称。
3. type是不是机器人已有工具。
4. params参数是否齐全、类型是否正确。
5. depends_on引用的步骤是否存在。
6. 步骤是否依赖自己。
7. 是否有循环依赖。
8. expect使用的结果字段是否真实存在。
9. 是否把stop_move等控制命令放进了普通计划。
10. 给每一步注入physical或parallel，不相信LLM的分类。
compile_plan()核心代码
def compile_plan(draft):
    if not isinstance(draft, dict):
        raise PlanError("计划必须是JSON对象")
    steps = draft.get("steps")
    if not isinstance(steps, list) or not steps:
        raise PlanError("steps必须是非空列表")
    if len(steps) > 12:
        raise PlanError("计划步骤不能超过12个")
    step_ids = set()
    # 第一轮：检查每个步骤本身
    for step in steps:
        step_id = step.get("id")
        task_type = step.get("type")
        params = step.get("params", {})
        dependencies = step.get("depends_on", [])
        if not step_id or step_id in step_ids:
            raise PlanError(f"步骤id无效或重复：{step_id}")
        step_ids.add(step_id)
        if task_type not in PLANNER_VISIBLE_TYPES:
            raise PlanError(f"不允许使用工具：{task_type}")
        if task_type in CONTROL_TYPES:
            raise PlanError("stop等控制命令不能进入普通计划")
        validate_params(
            task_type,
            params,
            TASK_SPECS[task_type],
        )
        if not isinstance(dependencies, list):
            raise PlanError("depends_on必须是列表")
        if step_id in dependencies:
            raise PlanError(f"{step_id}不能依赖自己")
    # 第二轮：检查依赖目标是否存在
    for step in steps:
        for dependency in step["depends_on"]:
            if dependency not in step_ids:
                raise PlanError(
                    f"{step['id']}依赖不存在的步骤："
                    f"{dependency}"
                )
    # 第三轮：拓扑排序检查循环
    topological_order = topological_sort(steps)
    # 第四轮：由程序注入执行分类
    compiled_steps = []
    for index, step in enumerate(steps):
        task_type = step["type"]
        compiled_steps.append({
            **step,
            "_execution": (
                "parallel"
                if task_type in PARALLEL_TYPES
                else "physical"
            ),
            "_order": index,
            "_timeout": TASK_SPECS[task_type].timeout,
        })
    return {
        "goal": draft["goal"],
        "steps": compiled_steps,
        "_topological_order": topological_order,
    }
循环依赖检查核心：
def topological_sort(steps):
    indegree = {
        step["id"]: len(step["depends_on"])
        for step in steps
    }
    children = {
        step["id"]: []
        for step in steps
    }
    for step in steps:
        for dependency in step["depends_on"]:
            children[dependency].append(step["id"])
    ready = [
        step_id
        for step_id, count in indegree.items()
        if count == 0
    ]
    result = []
    while ready:
        step_id = ready.pop(0)
        result.append(step_id)
        for child in children[step_id]:
            indegree[child] -= 1
            if indegree[child] == 0:
                ready.append(child)
    if len(result) != len(steps):
        raise PlanError("计划存在循环依赖")
    return result

十一、ready步骤到底是什么
一个步骤是ready，需要同时满足：
步骤状态仍然是PENDING
+
depends_on中的所有步骤都是SUCCEEDED
+
没有收到stop_move
核心判断只有这一段：
ready = [
    step
    for step in steps
    if (
        states[step["id"]] == "pending"
        and all(
            states[dependency] == "succeeded"
            for dependency in step["depends_on"]

    )
]
例如：
A：打开药箱，无依赖
B：读取RGB状态，无依赖
C：检查药箱，依赖A
D：找张三，依赖C
E：返回门口，依赖D
初始：
A ready，physical
B ready，parallel
C 不ready
D 不ready
E 不ready
所以A和B可以一起开始。
A完成后：

→ C变成ready
C结果满足 state_name == open 后：
D变成ready

十二、run_plan()核心代码
run_plan()负责真正按照依赖执行。
它不断重复以下过程：
查找ready步骤
→ 启动一个物理步骤
→ 启动最多四个安全并行步骤
→ 等待任意步骤完成
→ 保存结果
→ 重新计算ready步骤
步骤成为ready需要：
当前状态是PENDING
+
所有depends_on步骤都是SUCCEEDED
+
没有收到stop_move
例如：
A：打开药箱
B：检查药箱，依赖A
C：读取RGB缓存
D：找张三，依赖B
最开始：
A ready
C ready
B、D不ready
所以：
A拿physical_lock
C使用parallel_slots
A和C可以同时运行
A成功后B才ready。B结果满足药箱已打开后，D才ready。
run_plan()核心代码
async def run_plan(self, plan):
    states = {
        step["id"]: "pending"
        for step in plan["steps"]
    }
    results = {}
    running = {}
    while True:
        if self.stop_event.is_set():
            break
        pending = [
            step
            for step in plan["steps"]
            if states[step["id"]] == "pending"
        ]
        if not pending and not running:
            break
        ready = [
            step
            for step in pending
            if all(
                states[dependency] == "succeeded"
                for dependency in step["depends_on"]
            )
        ]
        physical_running = any(
            step["_execution"] == "physical"
            for step in running.values()
        )
        # 最多启动一个物理任务
        if not physical_running:
            physical_step = next(
                (
                    step
                    for step in ready
                    if step["_execution"] == "physical"
                ),
                None,
            )
            if physical_step:
                states[physical_step["id"]] = "running"
                task = asyncio.create_task(
                    self.run_step(physical_step)
                )
                running[task] = physical_step
        # 最多启动四个并行任务
        parallel_running = sum(
            step["_execution"] == "parallel"
            for step in running.values()
        )
        available = 4 - parallel_running
        for step in [
            item
            for item in ready
            if item["_execution"] == "parallel"
            and states[item["id"]] == "pending"
        ][:available]:
            states[step["id"]] = "running"
            task = asyncio.create_task(
                self.run_step(step)
            )
            running[task] = step
        if not running:
            raise RuntimeError("计划依赖无法继续")
        done, _ = await asyncio.wait(
            running,
            return_when=asyncio.FIRST_COMPLETED,
        )
        for task in done:
            step = running.pop(task)
            outcome = task.result()
            states[step["id"]] = outcome["state"]
            results[step["id"]] = outcome
            if outcome["state"] != "succeeded":
                self.stop_event.set()
                break
    return {
        "success": all(
            state == "succeeded"
            for state in states.values()
        ),
        "states": states,
        "results": results,
    }
执行一个步骤：
async def run_step(self, step):
    guard = (
        self.parallel_slots
        if step["_execution"] == "parallel"
        else self.physical_lock
    )
    async with guard:
        if self.stop_event.is_set():
            return {
                "state": "canceled",
                "error_msg": "计划已停止",
            }
        result = await self.agent.execute_task({
            "type": step["type"],
            "params": step["params"],
        })
    if result.get("success") is not True:
        return {
            "state": "failed",
            "result": result,
            "error_msg": result.get(
                "error_msg",
                "任务执行失败",
            ),
        }
    if not check_expect(
        result,
        step.get("expect"),
    ):
        return {
            "state": "failed",
            "result": result,
            "error_msg": "任务结果不符合预期",
        }
    return {
        "state": "succeeded",
        "result": result,
        "error_msg": "",
    }

十四、当前同步阻塞必须处理
一把物理锁解决的是“两个任务争机器人”，不能解决“事件循环被同步函数卡住”。
当前例如：
elif task_type == "find_person":
    return self.ros2_interface.find_person(...)
find_person() 内部可能等待ROS服务30秒。在这30秒内，stop消息可能无法及时执行。
过渡改法是将经过确认可在线程执行的同步函数放入 asyncio.to_thread()：
import functools
async def run_sync(function, *args, **kwargs):
    call = functools.partial(
        function,
        *args,
        **kwargs,
    )
    return await asyncio.to_thread(call)
这时过程变成：
主事件循环把同步ROS函数交给工作线程
→ 主事件循环立即空闲
→ 可以继续处理stop_move
→ 工作线程完成后返回结果
例如：
elif task_type == "find_person":
    return await run_sync(
        self.ros2_interface.find_person,
        params.get("obj_name", ""),
        params.get("user_prompt", ""),
    )
药箱查询：
elif task_type == "get_medicine_box_status":
    result = await run_sync(
        self.ros2_interface.get_medicine_box_status
    )
    result["type"] = task_type
    return result
优先处理：
- find_person
- _call_ros2_service_async()中的同步轮询
- _call_ros2_service()外部命令调用
- 药箱和灯光里的time.sleep()
- navigate_to_position()
- 所有可能等待数秒的同步工具
长期更合适的是把长物理操作改为真正的ROS2 Action，但不影响当前编排架构。
